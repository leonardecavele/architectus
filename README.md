`libft-tester` is a collection of tests for the mandatory and bonus functions of the 42 Libft project.

Each test compares the result of a custom function with the expected behaviour. Tests run in separate processes, allowing segmentation faults to be reported without stopping the entire suite.

This tester is intended as a debugging aid and should not replace manual verification or other testers.

### Installation

Clone the repository inside your Libft directory:

```bash
cd path/to/libft
git clone https://github.com/leonardecavele/libft-tester
cd libft-tester
```

The tester is designed for GNU/Linux and requires Bash, GNU Make and `libbsd`. Norminette is only required for the norm check.

### Commands

| Command               | Action                              |
| --------------------- | ----------------------------------- |
| `make`                | Run all mandatory and bonus tests   |
| `make m`              | Run mandatory tests                 |
| `make b`              | Run bonus tests                     |
| `make ft_strlen.test` | Run one specific test               |
| `make r`              | Check mandatory relinking           |
| `make rb`             | Check bonus relinking               |
| `make check`          | Check mandatory filenames           |
| `make checkb`         | Check mandatory and bonus filenames |
| `make n`              | Run Norminette                      |
| `make libft.a`        | Rebuild the library                 |
| `make clean`          | Remove compiled tests               |
| `make fclean`         | Remove compiled tests and `libft.a` |

Replace `ft_strlen` with the name of the function you want to test.

### Test executables

A `.test` file is a normal executable generated by the Makefile. The extension is only used to distinguish test programs from source files.

For example, this command:

```bash
make ft_strlen.test
```

Compiles `tests/ft_strlen.c` together with the shared testing utilities from `tester.c`, then links the result against `../libft.a` and `libbsd`.

The generated executable is stored as:

```text
bin/ft_strlen.test
```

It is then executed automatically. Running `make` repeats this process for every mandatory and bonus function listed in `list.mk`.

### Results

Successful comparisons are displayed in green, while incorrect results appear in red with the actual and expected values.

If a tested function crashes, the tester reports the segmentation fault and continues with the remaining tests.
